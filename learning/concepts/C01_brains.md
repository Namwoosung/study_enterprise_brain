# C1. Second Brain에서 Enterprise Brain까지

**목표:** 두 용어의 목적과 범위를 설명하고, 조직 지식 시스템에 필요한 구성 요소를 기술 제품과 구분한다.

이 경로는 처음부터 읽는 개념 교재다. 반도체 지식은 로트(함께 추적하는 생산 묶음), 장비, 작업 이력, 절차 문서 정도면 충분하다. 모든 E01·L02·D02 사례는 [교육용 합성 자료](../case/README.md)이며 실제 공정의 인과관계를 주장하지 않는다.

<a id="c1-01"></a>
## 1. 왜 지식을 밖에 저장하려 하는가?

프로그래머가 모든 API를 외우지 않고 문서·코드·이슈를 참조하듯, 업무 지식도 머리 밖에 저장해 다시 사용할 수 있어야 한다. 그런데 저장과 활용은 다르다. PDF 1만 개를 모아도 어떤 버전이 유효한지, 같은 이름의 장비가 같은 대상인지, 누가 승인했는지를 모르면 업무 질문에 답하기 어렵다.

이 교재에서는 네 단계를 구별한다. **기록**은 원래 남은 문서나 행이고, **정보**는 그 기록에서 읽은 내용이며, **지식 주장**은 맥락을 붙여 재사용할 수 있도록 표현한 명제다. **판단**은 그 주장과 정책을 바탕으로 행동을 결정하는 일이다. 이는 설명을 위한 구분이지 보편적으로 합의된 엄격한 계층 법칙은 아니다.

예를 들어 “RUN002, E01, D02”라는 행은 기록이다. “RUN002가 E01에서 D02를 사용했다”는 해석은 매핑을 거친 주장이다. “올바른 문서를 사용했다”는 판단에는 작업 시각, 문서 적용 대상·유효 기간까지 필요하다. “이 로트를 출하하라”는 행동은 다시 별도의 권한과 승인 문제다.

<a id="c1-02"></a>
## 2. Second Brain은 무엇이며 왜 시작됐는가?

Second Brain은 기억·아이디어·참고자료를 외부 시스템에 남겨 사고와 산출물 제작을 돕는 개인 지식 관리 접근으로 이해할 수 있다. 여기서는 Tiago Forte가 설명하는 방법론을 기준으로 삼는다. 그의 CODE는 Capture(수집), Organize(정리), Distill(핵심 추리기), Express(표현·활용)다. 정보 과잉 속에서 저장한 것을 다시 작업에 사용하는 것이 핵심이다. 특정 노트 앱, 그래프 DB, LLM을 필수로 요구하는 기술 규격이 아니다. [원저자의 입문 안내](https://fortelabs.com/blog/basboverview/)

이를 이번 공부에 적용하면 공식 문서를 모으고, “표현·검증·검색”이라는 목적에 따라 정리하고, 반례를 짧게 남긴 뒤 발표 설명에 사용하는 흐름이 된다. 폴더로 구현해도, 링크된 노트로 구현해도 된다. 모든 노트를 RDF로 바꾸는 것이 목적은 아니다.

개인에게는 “내가 이해하는 약칭”도 유용하다. 그러나 다른 사람이 그 노트를 업무 근거로 사용하려면 작성자의 기억에 의존하던 맥락을 밖으로 꺼내야 한다. 이것이 개인 지식 관리에서 조직 지식 관리로 넘어갈 때 생기는 중요한 변화다.

<a id="c1-03"></a>
## 3. Enterprise Brain은 정확히 무엇인가?

이 교재에서 Enterprise Brain은 **조직의 자료·업무 의미·경험·정책을 연결하고, 사람과 소프트웨어가 적절한 맥락에서 재사용하도록 유지하는 체계**라는 작업 정의로 사용한다. RDF처럼 명세가 하나로 정해진 표준 데이터 모델이라고 취급하지 않는다.

이름 자체는 제품명으로도 쓰인다. WRITER는 Enterprise Brain을 조직의 공유 맥락 계층으로 소개한다. 이 공급사 설명은 용어의 실제 사용례이며, 모든 기업 지식 시스템이 그 제품 구조를 따라야 한다는 근거는 아니다. [WRITER 공식 소개, 2026-09-09](https://writer.com/blog/enterprise-brain/)

등장 배경을 이해할 때는 “AI가 똑똑해졌다”보다 **조직의 정보가 여러 시스템에 흩어져 있고 업무 의미가 암묵적이라는 문제**를 먼저 본다. DB의 status=R, 회의록의 “재확인”, 개인 메모의 “주의”는 서로 관련될 수 있지만 자동으로 같은 판정을 뜻하지 않는다. AI가 조직 맥락을 재사용하려면 이 차이를 보존해야 한다. 이 문제 설정은 본 교재의 사례 분석이다.

<a id="c1-04"></a>
## 4. 조직의 뇌를 구성하는 역할을 분해하기

아래는 정답 아키텍처가 아니라 기능을 빠뜨리지 않기 위한 교재의 분해다.

| 역할 | 묻는 질문 | 합성 사례 |
|---|---|---|
| 원천 연결 | 어디에 어떤 기록이 있는가? | 생산 CSV, 절차 PDF, 회의록 |
| 의미 정리 | 코드와 용어는 무엇을 뜻하는가? | review_flag는 확정 불량인가? |
| 식별·연결 | 어떤 대상·사건에 대한 기록인가? | NORTH 검사기 1호 → E01 |
| 검증·승인 | 어떤 범위에서 사용할 수 있는가? | 경험담과 승인 절차 구분 |
| 저장·검색 | 필요한 근거를 어떻게 가져오는가? | 작업 경로와 문서 본문 결합 |
| 제공·행동 | 누가 무엇에 사용할 수 있는가? | 근거 답변, 승인된 Agent 도구 |
| 운영 | 변경되면 무엇을 다시 계산하는가? | D02 정정 후 요약·색인 갱신 |

Knowledge Graph는 이 중 대상·관계를 표현하고 연결하는 데 활용될 수 있다. Ontology는 의미를 정하는 데, Graph DB는 저장·질의에, RAG는 답변 근거 구성에 관여한다. 따라서 “Enterprise Brain을 설치한다”는 말만으로 수집·권한·검토 문제가 해결되는 것은 아니다.

<a id="c1-05"></a>
## 5. 심화: 기억·맥락·행동을 구분하기

조직의 장기 지식과 한 사용자의 대화 기록은 수명과 신뢰 조건이 다르다. 대화에서 “장비를 A라고 부르자”라고 합의했다고 전사 자산 ID가 바뀌면 안 된다. 개인 선호, 임시 작업 상태, 승인된 정책, 기록된 사실을 별도 범위로 취급해야 한다.

**맥락**은 질문에 필요한 지식의 선택이다. 모든 데이터를 프롬프트에 넣는 것이 아니다. “RUN002 때의 절차는?”에는 당시의 유효 시각이 필요하고, “당시 서비스가 알고 있었나?”에는 수집 시각이 필요하다. **행동**에는 추가 통제가 필요하다. 절차를 설명할 권한과 설비 설정을 바꿀 권한은 다르다.

출처·생성 활동·책임 주체를 연결하는 표준 모델로 PROV-O의 Entity·Activity·Agent를 참고할 수 있다. 이때 Agent는 책임을 지는 사람·조직·소프트웨어 등을 포괄하는 provenance 용어이며, 요즘 말하는 자율 LLM Agent만 뜻하지 않는다. [PROV-O 시작 개념](https://www.w3.org/TR/prov-o/#description-starting-point-terms)

<a id="c1-06"></a>
## 6. 심화: 한 곳에 복사해야만 조직 지식이 되는가?

물리적으로 통합하면 반복 검색이 쉬워질 수 있지만 원본 변경 반영과 복제 데이터의 권한을 관리해야 한다. 원천에 질의하는 가상 접근은 최신 값을 읽는 데 유리할 수 있지만 원천 장애·지연·질의 권한에 의존한다. 문서 색인은 복제하고 정형 사실은 원천에 조회하는 혼합 방식도 가능하다.

이 선택은 “기업 지식 = 거대한 중앙 그래프”라는 전제를 피하게 한다. R2RML도 관계형 데이터를 RDF로 보는 매핑을 정의하며 결과를 물리적으로 저장하는 방식과 가상 접근 구현을 구분할 수 있다. [R2RML 개요](https://www.w3.org/TR/r2rml/#overview)

본 사례에서는 자주 쓰는 장비 식별·문서 메타데이터를 연결하고, 큰 원문은 별도 보관하며, 근거 위치로 되돌아가는 설계를 검토할 수 있다. 이것은 제안이지 모든 반도체 기업에 검증된 해법은 아니다.

<a id="c1-07"></a>
## 7. 발표에서 설명할 수준과 확인 문제

**꼭 설명:** Second Brain의 개인 재사용 목적, Enterprise Brain의 작업 정의, 조직에서 추가되는 공유 의미·권한·시간·책임, KG·DB·RAG의 역할 차이. **지금 생략 가능:** 특정 노트 앱 운영법, 공급사별 배포 메뉴와 가격.

**확인 질문:** 개인 노트를 모두 공유 폴더로 옮기면 Enterprise Brain이 되는가? Neo4j 도입과 Enterprise Brain 구축은 왜 같은 말이 아닌가?

### 해설

공유만으로 용어의 의미·승인 상태·적용 시점이 합의되지는 않는다. Neo4j는 저장과 질의를 담당할 수 있지만 데이터의 의미·검토·원천 갱신 책임까지 결정하지 않는다. 발표에서는 “조직 지식을 재사용할 수 있는 상태로 유지하는 체계이며, 그래프는 이를 구현하는 한 수단”이라고 설명하고 자신의 범위를 덧붙인다.
