## 실제 예제의 읽기 공백

- L01 §3의 테이블은 첫 열이 ‘모델 T20’입니다. 앞의 D17은 개별 장비 E01의 부품 교체입니다. 같은 업무 사례라면 표에 E01과 모델 T20을 각각 두거나, 모델 전체에 적용하는 별개의 교재 상황이라고 설명해야 다른 T20 실물까지 P8로 바뀐다고 읽히지 않습니다.
- L01 69행에서 ‘E01 장비’의 표시 문자열 길이는 공백을 포함하면 6입니다. 언급 범위의 예는 글자 수를 지정하지 않아도 이해됩니다.
- L02의 A/B 대표점 계산은 각각 (1, 0)과 (1, 4)이며 (1, 1)의 거리는 1과 3, (1, 2)의 거리는 2와 2입니다. TransE 두 거리는 0과 3입니다. 예제는 실제 모델 좌표와 명확히 구별됐습니다.
- L03의 조건 표기 `(h, r, t, γ)`는 공개 v1 §6과 일치합니다. 공개 v1 §2.1의 일반 정의는 `(h, t, r)` 순서를 씁니다. L02에서 문헌별 순서를 확인하라고 했으므로 같은 논문 안에서도 표현이 달라지는 이 사례를 본문에 연결할 수 있습니다. [공개 v1 §2.1·§6](https://arxiv.org/html/2302.05019v1#S6)

## 전체 설명의 확인 범위

세 수업은 제목과 본문에서 논문을 별첨으로 읽는 위치를 명확히 합니다. 일반 KG 구축 전체를 논문 하나에 맞춰 좁히지 않고, D17의 실물·동일 지시·주장과 시간 제한을 써서 각 과제가 어떤 오류를 다루는지 보여 줍니다. 공개 v1 §4의 인식·타입·링킹·동일 지시·관계, §5의 completion·fusion, §6의 조건 추출·조건부 예측·시간에 따른 움직임, §7의 저장과 §8의 과제를 실제 예와 대조했습니다. 원문의 기술 설명을 교재의 운영 정책으로 곧바로 해석하지 않고 학습 전·중·후 확인 질문을 제공합니다. 위 요구사항 보강 후에는 실제 본편 링크와 웹의 별첨 그룹을 확인할 수 있습니다.
