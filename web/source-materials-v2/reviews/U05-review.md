## 기술 검토

| 결과 | 발견과 재확인 | 다음 수정 또는 확인 |
| --- | --- | --- |
| 해결 | ‘같은 모델을 표와 그래프에 옮겨 봅니다’의 초기 그래프 예시에는 장착 노드의 위치와 유효구간이 없어 Q3의 두 시각을 재구성하기 어려웠습니다. 수정된 예는 I-01과 I-02 모두에 장비 A-07, 부품 ID, 같은 위치 slot-1, 효력 시작·종료를 표시합니다. 10:29와 10:30을 각각 대입해 P-11과 P-17을 확인했습니다. | 예제의 관측 범위에서만 종료 미상인 구간을 사용한다는 설명을 유지합니다. B01의 그래프 시점 판정에 대한 차단은 해소됐습니다. |
| 해결 | ‘답하고 싶은 질문’의 초기 Q4는 작업지시 상태를 실행 건수 집계의 필수 입력처럼 표현했습니다. 수정된 질문과 답변은 장비·기간으로 고른 정비 수행 ID를 셉니다. E-01 및 E-02가 두 건이고, 세 장의 지시서는 계획·취소를 대조하는 자료입니다. | 문서에 완료로 표시된 건수와 실제 수행 사건 건수가 달라질 수 있다는 전개가 데이터 모델 선택과 연결됩니다. |
| 보완 | ‘어떤 의미를 먼저 합의해야 할까요’에서 SKOS의 `skos:broader`를 ‘바로 위’를 가리킨다고 표현합니다. 직접 계층에 쓰는 관례이며 표준의 의미 규칙이 직접성 또는 유일한 상위를 강제하지는 않습니다. | ‘좁은 개념을 더 넓은 개념에 연결하고, 관례상 직접 상위를 적습니다’로 풀면 설계 관례와 형식 의미를 구별할 수 있습니다. [SKOS Reference §8.1, §8.6.6, §8.6.9](https://www.w3.org/TR/skos-reference/#semantic-relations) |
| 확인 | 같은 절에서 SKOS 개념의 상하 관계만으로는 개별 장비의 상위 클래스 소속을 결론 내릴 수 없다고 설명합니다. 후반부의 RDF 문장에서는 A-07의 식각 장비 소속과 식각 장비의 하위 클래스 선언을 결합해 공정 장비 소속을 도출합니다. `hasModel`은 두 개체를 연결하는 별도 관계로 읽습니다. | 원고의 구분이 맞습니다. 대체 레이블은 분류 메뉴 표현이고 모델 사양 참조는 실물과 제품 모델 관계라는 사례를 유지합니다. [SKOS Reference §3.5.1, §5, §8](https://www.w3.org/TR/skos-reference/#concepts), [OWL 2 Primer §4.1–4.2, §4.4](https://www.w3.org/TR/owl2-primer/#Classes_and_Instances) |
| 확인 | ‘같은 모델을 표와 그래프에 옮겨 봅니다’의 입력 검사는 저장 요건의 점검이며 하위 클래스 공리는 분류 귀결을 뒷받침합니다. AL-02에 확인 연결이 기록돼 있지 않다는 Q6 답은 실제 결함이 없었다고 단정하지 않습니다. | 개정 이후의 자료 범위와 원인 관계를 별도로 다루는 설명을 유지합니다. [OWL 2 Primer §2–3](https://www.w3.org/TR/owl2-primer/#What_is_OWL_2.3F) |

세 Turtle 문장에 예제 기본 접두어와 표준 `rdf`, `rdfs` 접두어를 선언해 저장소 가상환경의 RDFLib 7.6.0에서 파싱했습니다. 그래프에는 명시한 트리플 세 건이 들어가고, `rdf:type/rdfs:subClassOf` 경로 질의가 A-07의 공정 장비 분류를 반환합니다. 명시 트리플만 읽으면 공정 장비 소속 문장은 저장돼 있지 않습니다. 여기서 확인한 실행은 구문 파싱과 경로 질의이며 OWL 추론기를 호출한 결과는 없습니다. [Turtle §2.4](https://www.w3.org/TR/turtle/#sec-iri)

## 설명 검토

| 결과 | 입문 독자의 질문 | 수정 방법 |
| --- | --- | --- |
| 보완 | 용어 비교 표에서 ‘클래스’, ‘공리’, ‘OWL’이 정의보다 먼저 등장합니다. 앞 단원을 읽은 독자도 ‘공리’가 관계의 이름인지, 그 관계를 적은 문장인지 알기 어렵습니다. | 첫 등장에 클래스는 ‘같은 정의를 공유하는 대상의 범주’, 공리는 ‘사실이나 관계의 일반 규칙을 표현한 선언’이라는 짧은 정의를 붙이거나 뒷 절을 가리킵니다. OWL을 논리적 의미를 갖는 온톨로지 표현 언어라고 처음 나올 때 풀어도 됩니다. [OWL 2 Primer §2–3](https://www.w3.org/TR/owl2-primer/#What_is_OWL_2.3F) |
| 보완 | Turtle 예제는 마침표, `rdf:type`, `rdfs:subClassOf`를 읽는 법을 제공합니다. ‘접두어 선언을 생략’만으로는 콜론이 있는 `:AssetA07`과 `rdf:type`의 콜론이 같은 원리인지, `:hasModel`이 예제에서 만든 관계인지 알기 어렵습니다. | U04의 [Turtle 설명](../units/U04/01-rdf-language.md)을 가리키고, `:`는 앞 이름을 비워 쓴 예제 접두어, `rdf:`와 `rdfs:`는 표준 이름의 접두어, `:hasModel`은 예제에서 정의한 ‘제품 모델을 참조함’이라고 한 문장씩 연결합니다. 코드의 목적이 읽기라면 지금처럼 생략을 표시해도 되며, 복사 실행을 제공할 경우 선언 3개도 포함합니다. [Turtle §2.4](https://www.w3.org/TR/turtle/#sec-iri) |
| 보완 | 새 장착 이력에서 `2026-11-18T10:30:00+09:00`를 어떻게 읽는지, SQL 쪽의 `asset.model_id`가 하나의 이름인지 표와 열을 나눈 표기인지 첫 등장에 풀 수 있습니다. | 날짜 뒤 T가 시각의 시작을, +09:00이 예제의 한국 표준시를 나타낸다고 설명합니다. `asset.model_id`는 asset 표의 model_id 열로 풀어 씁니다. |
| 보완 | 단위 예에서 수치가 같은 Pa와 mbar 기록이 실제로 어떻게 다른지는 문장만 읽고 확인하기 어렵습니다. | Pa는 파스칼, mbar는 밀리바라고 먼저 풉니다. 1 mbar = 100 Pa이므로 8 mbar는 800 Pa라는 값을 보여주면 ‘값·단위를 같이 관리한다’는 결정이 자연스럽습니다. |
