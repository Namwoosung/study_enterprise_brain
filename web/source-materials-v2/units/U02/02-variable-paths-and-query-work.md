# 경로가 길어지면 무엇을 계산하나요?

앞 수업에서는 작성자에서 팀장까지 정해진 연결을 읽었습니다. 이번 질문은 “제품 P를 수정하면 어떤 상위 조립품에 영향이 갈까요?”입니다. 어느 제품은 두 층, 다른 제품은 일곱 층의 상위 부품에 들어갑니다. 연결의 길이를 미리 한 가지로 정하기 어렵습니다. 이때 그래프 탐색이 자연스러운 이유와, 관계형 데이터베이스에서도 같은 문제를 푸는 방법을 함께 보겠습니다.

여기서 부품 구성은 실제 반도체 장비의 설계가 아닌 합성 자료입니다. 조립품은 다른 부품을 포함해 만든 단위를 뜻합니다. 이 수업에서는 각 포함 관계의 수량을 1로 두고, **어떤 상위 조립품에 들어가는가**만 묻습니다. 필요한 부품 총수 계산은 같은 부품을 여러 경로로 쓰는 수량 계산이므로 다른 문제입니다.

## 직접 연결과 도달 가능한 대상을 구별합니다

다음 여섯 행에서 `parent`는 포함하는 쪽, `child`는 포함되는 쪽입니다. 같은 P가 A와 B 양쪽에 들어갑니다. 두 조립품은 같은 최상위 제품 X에 들어가고, X는 다시 Z에 들어갑니다.

| parent | child |
|---|---|
| A | P |
| B | P |
| X | A |
| X | B |
| Z | X |
| Y | Q |

포함 방향으로 그리면 `Z → X → A → P`와 `Z → X → B → P`가 있습니다. P에서 **사용되는 상위**를 찾을 때는 저장 방향의 반대로 올라갑니다. 관계의 방향과 탐색하는 방향은 따로 설명해야 합니다. P의 직접 상위는 A·B 두 개입니다. 한 단계를 더 올라가면 두 경로에서 모두 X가 나옵니다. 그다음에는 Z입니다. Q와 Y는 P와 이어지지 않아 결과에 없습니다.

| 반복 단계 | 직전 단계의 대상 | 이번에 찾은 상위 | 처음 발견한 상위 |
|---|---|---|---|
| 시작 | P | — | — |
| 1 | P | A, B | A, B |
| 2 | A, B | X, X | X |
| 3 | X | Z | Z |
| 4 | Z | 없음 | 없음, 종료 |

이 표의 오른쪽처럼 이미 방문한 대상을 기억하면 X를 상위 조립품 목록에 한 번만 넣습니다. 중간의 X 두 개는 서로 다른 두 제품이 아닙니다. **목적지의 집합**과 **그곳에 가는 경로의 목록**을 혼동하지 않아야 합니다. X에 닿는 경로가 두 개라는 정보는 별도로 의미가 있습니다. 부품 P가 어느 구성 가지에 사용되는지 보려면 두 경로를 모두 보여 줄 수 있습니다. 단순 영향 대상 목록은 A·B·X·Z 네 개입니다.

## 관계형 모델에서는 같은 표를 반복해서 읽습니다

RDB는 포함 관계를 `Contains(parent, child)` 표로 저장할 수 있습니다. 가변 길이 경로를 표현할 때 재귀 공통 테이블 식, 즉 **recursive CTE**를 사용할 수 있습니다. CTE는 한 질의 안에서 이름을 붙인 중간 결과입니다. 아래 질의는 SQLite로도 실행할 수 있는 작은 형태입니다.

```sql
WITH RECURSIVE Ancestor(id) AS (
  SELECT parent FROM Contains WHERE child = 'P'
  UNION
  SELECT c.parent
  FROM Contains AS c JOIN Ancestor AS a ON c.child = a.id
)
SELECT id FROM Ancestor ORDER BY id;
```

첫 `SELECT`가 출발 결과 A·B를 만듭니다. 다음 `SELECT`는 현재 찾은 상위의 ID를 다시 `child`에 맞춰 그 상위를 찾습니다. `UNION`은 같은 결과 행을 중복해서 추가하지 않습니다. 이 예의 행은 ID 하나이므로 X가 두 번 발견되어도 최종 집합은 하나입니다. `ORDER BY`는 결과 표시를 A·B·X·Z 순으로 정할 뿐, 검색이 반드시 그 순서로 실행된다는 의미는 아닙니다. PostgreSQL의 공식 설명에서도 재귀 부분의 결과를 반복 작업 표로 사용하고, `UNION`은 이미 나온 행을 제거합니다. [PostgreSQL 18 §7.8.2](https://www.postgresql.org/docs/18/queries-with.html#QUERIES-WITH-RECURSIVE)

`UNION ALL`로 바꾸고 경로도 함께 저장하면 각 경로를 보존할 수 있습니다. 이때 결과 행이 무엇인지를 다시 봐야 합니다. `(X, 깊이 2)`와 `(X, 깊이 4)`는 서로 다른 행입니다. ID가 같다는 이유만으로 중복 제거가 되지 않습니다. 순환까지 있으면 깊이가 늘어난 새 행이 계속 생길 수 있습니다. ‘방문한 ID’, 최대 깊이, 허용 경로를 질의 목적에 맞춰 관리해야 합니다.

작은 반례를 만들어 보세요. 입력 오류로 `P → Z`라는 포함을 추가하면 P에서 Z로 올라간 뒤 P로 돌아올 수 있습니다. 위의 ID만 반환하는 `UNION` 질의는 이미 본 ID가 다시 추가되지 않아 멈추지만, P 자신도 도달 집합에 포함될 수 있습니다. 프로그램이 종료했다는 사실이 입력의 조립 구조가 타당하다는 뜻은 아닙니다. 부품 구성이 순환하면 안 된다는 업무 규칙은 따로 검사해야 합니다.

## 속성 그래프에서는 반복 패턴을 요청합니다

각 부품을 `Part` 노드로, 포함을 `CONTAINS` 관계로 둡니다. `X-[:CONTAINS]->A`는 X가 A를 직접 포함한다는 뜻입니다. 다음은 Neo4j Cypher에서 읽을 수 있는 예입니다. 이 수업의 Cypher는 서버를 실행하지 않고 의미를 도출한 예상 결과입니다.

```cypher
MATCH (a:Part)-[:CONTAINS*1..3]->(:Part {id:'P'})
RETURN DISTINCT a.id
ORDER BY a.id
```

별표와 `1..3`은 여기서 관계를 1개부터 3개까지 이어 붙인 패턴을 뜻합니다. `(a)`에서 P로 내려가는 포함 경로를 찾지만, 결과로는 그 상위 a를 돌려줍니다. `DISTINCT`는 같은 상위의 ID가 여러 경로에서 나와도 한 번만 남깁니다. 위 자료에서 A·B는 1단계, X는 2단계, Z는 3단계 경로에 해당하므로 결과는 SQL과 같습니다. [Neo4j variable-length relationships](https://neo4j.com/docs/cypher-manual/current/patterns/variable-length-patterns/#quantified-relationships)

이 문법을 모든 길이를 제한 없이 찾아도 된다는 처방으로 읽지 마세요. 정해 놓은 최대 깊이 3은 예제 자료에는 충분하지만 제품 계층이 4층이면 놓칩니다. 업무가 허용하는 깊이, 순환 처리와 경로의 의미를 결정하고 질의 범위를 정해야 합니다. 최신 Cypher에는 반복 패턴의 다른 표기도 있으며 언어 버전에 따라 기능이 추가됩니다. 여기서는 자료를 읽는 데 필요한 반복 패턴의 뜻에 집중합니다.

SQL과 Cypher의 표현은 다르지만 둘 다 필요한 연결을 반복합니다. 관계형에서는 키 값을 조합하고, 그래프에서는 노드와 관계의 패턴을 드러냅니다. 어느 물리 연산으로 실행하는지는 엔진·인덱스·통계에 달려 있습니다. 그래프 그림에 선이 있다고 실행 비용까지 그림에서 바로 알 수는 없습니다.

## 방문한 노드 수와 경로 수가 다릅니다

경로가 많아지는 모양을 더 작게 계산해 보겠습니다. 시작점 S에서 A1·A2·A3 세 노드로 갈 수 있고, 각각에서 B1·B2·B3으로 갈 수 있으며, 각 B에서 T에 갈 수 있다고 가정합니다. 관계는 S의 3개, A에서 B로 9개, B에서 T로 3개로 총 15개입니다. 노드는 S·A 셋·B 셋·T로 8개입니다. 하지만 S에서 T까지 길이 3의 경로는 `3 × 3 × 1 = 9`개입니다.

다음 층을 계속 세 개씩 늘리면 노드를 공유해도 조합 경로는 빠르게 늘어납니다. 도달 가능한 대상만 필요하면 방문 집합으로 반복 확장을 줄일 수 있지만, 모든 경로가 결과라면 그 목록을 실제로 만들어 보내는 비용은 남습니다. ‘대상 하나 찾기’, ‘최단 경로 하나’, ‘모든 경로’, ‘모든 대상’은 다르게 요청해야 합니다.

**너비 우선 탐색(BFS)**은 출발점에서 한 단계 떨어진 대상을 먼저 보고 다음 층으로 넘어갑니다. 방문 집합을 사용하고 관계의 비용이 모두 같다면 처음 발견한 깊이로 최소 단계 수를 구할 수 있습니다. **깊이 우선 탐색(DFS)**은 한 가지를 더 깊이 따라간 뒤 돌아와 다음 가지를 봅니다. 입력을 따라 방문하는 순서의 차이입니다. DBMS의 모든 그래프 질의가 어느 한 알고리즘만 사용한다는 뜻은 아닙니다. 질의가 요구하는 경로와 엔진 계획을 봐야 합니다.

## 시작점을 얼마나 좁혔는지가 중요합니다

장비가 10만 대 있고 각 장비가 20개 관측을 가졌다고 합시다. E01의 관측을 찾을 때 두 가지 논리 전략을 생각할 수 있습니다. 모든 장비의 관측 200만 건을 펼친 뒤 E01만 남기거나, E01을 먼저 찾은 뒤 그 20개를 펼치는 것입니다. 이 숫자는 설명용 후보 수이며 DB의 실제 읽기 횟수나 응답 시간은 아닙니다.

조건이 전체 후보에서 얼마나 적게 남기는지 **선택도(selectivity)**로 생각할 수 있습니다. 매우 흔한 상태 ‘운영 중’과 유일한 장비 ID는 남기는 범위가 다릅니다. ID 인덱스가 시작점 탐색을 돕고, 관계 타입·방향·날짜 제한이 이후 확장을 줄일 수 있습니다. 반대로 시작 장비가 전사 문서 허브에 연결되어 있으면 그 이웃 하나에서 후보가 크게 늘 수 있습니다. 한 노드에 연결된 관계 수를 그 노드의 **차수(degree)**라고 부릅니다. 평균 차수만으로 이런 허브의 비용을 예상하기 어렵습니다.

Neo4j의 실행 연산 `Expand(All)`은 주어진 노드에서 패턴이 지정한 방향과 관계를 확장합니다. 시작점을 찾는 연산과 이 확장 연산의 역할은 다릅니다. 직접 연결을 다루기 편한 구조여도, 어떤 노드를 찾는지와 몇 관계를 검사하고 몇 행을 내보내는지가 전체 일을 결정합니다. [Neo4j execution operators: Expand All](https://neo4j.com/docs/cypher-manual/current/planning-and-tuning/operators/operators-detail/#query-plan-expand-all)

## 설명 연습

**1.** 같은 부품 P가 두 조립품을 거쳐 X에 들어갑니다. `RETURN a.id`에 X가 두 행 나왔으니 실제 제품 X가 두 개라고 말해도 되나요?

두 경로의 매칭 결과가 같은 노드를 가리킨 것일 수 있습니다. 목적지 ID와 경로를 함께 확인합니다. 영향 대상은 X 한 개로 셀 수 있고, 구성 경로의 수는 두 개로 셀 수 있습니다. 수량 문제라면 경로마다 포함 수량을 곱하고 합칠 별도 모델이 필요합니다.

**2.** 모든 상위 조립품을 보려는데 최대 깊이를 2로 고정했습니다. 위 자료에서 어떤 답이 빠지나요?

Z가 빠집니다. P까지 세 관계를 거쳐 내려오기 때문입니다. 짧은 제한이 속도를 개선해도 필요한 답을 누락하면 같은 질문의 개선이라고 평가할 수 없습니다.

**3.** 입력 순환을 막았더니 모든 경로를 출력해도 빨라질까요?

순환이 없는 층형 그래프에도 경로 조합이 많을 수 있습니다. 8개 노드 예의 9개 경로처럼 노드를 공유해도 경로는 여러 개입니다. 출력이 대상 집합인지 전체 경로인지부터 확인해야 합니다.
